# Мера

Учебное приложение на React, TypeScript и Vite. В первой практической работе собраны пять калькуляторов погрешностей. Вторая добавляет численное дифференцирование и построение графиков.

## Запуск из ZIP с SQLite

Распакуйте архив, откройте терминал в папке `mera` и запустите сервер. Для готовой сборки достаточно Python 3.9 или новее.

```sh
python3 server/app.py
```

Откройте [приложение](http://127.0.0.1:8000/). Сервер создаст базу `data/history.sqlite3` при первом запуске. История останется в файле после остановки программы.

## Запуск из исходников

Понадобятся Python и Node.js 20.19+ или 22.12+. Из корня репозитория выполните следующие команды.

```sh
npm ci
npm run start:sqlite
```

Эта команда собирает приложение и запускает сервер по адресу `http://127.0.0.1:8000/`. При разработке оставьте сервер запущенным и выполните `npm run dev` во втором терминале. Vite направляет запросы `/api` на порт 8000. Проверки запускаются командами `npm test` и `npm run test:sqlite`.

## Публикация на GitHub Pages и Render

GitHub Pages раздаёт интерфейс приложения. Все восемь инструментов отправляют исходные значения и результаты в Python API на Render. Сервер записывает их в PostgreSQL. Служебная cookie содержит только случайный идентификатор сессии. По нему сервер находит расчёты конкретного посетителя. [Приложение на GitHub Pages](https://zalupkins1717-ops.github.io/college/)

1. В Render выберите **New → Blueprint**, подключите репозиторий `zalupkins1717-ops/college` и ветку `main`. Файл `render.yaml` в корне задаёт Python-сервис `mera-college-api` и базу `mera-college-db` в регионе Oregon. Оба ресурса используют план Free. Доступ к базе идёт по внутренней сети. Render передаёт строку подключения серверу через переменную `DATABASE_URL`.
2. После запуска скопируйте выданный Render HTTPS-адрес сервиса. В сборке для Pages значение `VITE_HISTORY_API_URL` должно указывать на этот адрес с путём `/api`. Публичный адрес API можно включить в сборку, а пароль от PostgreSQL остаётся на сервере. Переменная `MERA_FRONTEND_ORIGIN` в Blueprint разрешает запросы с `https://zalupkins1717-ops.github.io`.
3. В репозитории откройте **Settings → Pages** и выберите **GitHub Actions**. При обновлении ветки `main` workflow проверяет и собирает интерфейс и публикует `dist/`. Внутренние ссылки, например `/college/#/area`, открываются напрямую благодаря `HashRouter`.

Стоимость двух экземпляров Free составляет $0 в пределах включённых лимитов. Бесплатная база Render Postgres работает 30 дней со дня создания. После 15 минут простоя бесплатный веб-сервис засыпает, поэтому первый запрос после перерыва может занять около минуты. [Условия бесплатного тарифа Render](https://render.com/docs/free)

## Возможности

Пять калькуляторов охватывают исходные задания:

- **Фактическая погрешность:** абсолютная и относительная ошибки приближения.
- **Округление и усечение:** сравнение результатов, фактических ошибок и их границ.
- **Арифметические операции:** сложение, вычитание, умножение и деление с границами погрешностей.
- **Площадь прямоугольника:** единицы измерения, диапазон возможной площади и проверка процентного допуска.
- **Вычитание близких чисел:** рост относительной погрешности при малой разности.

Поддерживаются ввод десятичной запятой, проверка исходных данных, формулы и шаги решения, примеры и сброс полей. В истории можно просмотреть исходные данные и результаты, восстановить расчёт и выгрузить записи в CSV. Справочник объясняет используемые обозначения и формулы.

### Практическая работа № 2. Численные методы

- **Производная.** Введите выражение и точку. Для `x^2` при `x = 3` двусторонняя разность даёт примерно 6. Пустое поле шага включает автоматический подбор.
- **Частная производная.** Выберите x, y или z и задайте координаты точки. Для `x^2*y + sin(z)` в точке (2, 3, 0) по x получится примерно 12, по y — 4, по z — 1.
- **График.** Введите функцию одной переменной и интервал. Например, у `1/x` на [−4, 4] две ветви. График строится по выборке точек с дополнительными проверками между ними. Углы задаются в радианах.

### Декоратор и история всех восьми инструментов

Оба сервиса расчётов используют метод с декоратором `@recordCalculation` из `src/shared/history/recordCalculation.ts`. После успешного вычисления он записывает дату, название инструмента, введённые параметры и результат через единый интерфейс хранилища. Для графика сохраняются также вычисленные точки. Ошибка выражения не создаёт запись. Если хранилище недоступно, пользователь видит результат и отдельное сообщение об ошибке записи.

Пять прежних калькуляторов сохраняют результат после короткой паузы при изменении значений. Кнопка сохранения позволяет записать текущий расчёт сразу. Производные и графики сохраняются по кнопке выполнения. Открытие страницы или восстановление истории само по себе не создаёт повторную запись. Для одного пользователя хранятся последние 50 расчётов.

При запуске на компьютере Python записывает историю в SQLite. Для другого порта или имени файла используйте `python3 server/app.py --port 8080 --db data/demo.sqlite3`. На Render сервер использует PostgreSQL, доступный по `DATABASE_URL`. В таблице `calculations` хранятся расчёты, а таблица `sessions` связывает каждую историю с её владельцем.

## Структура

```text
src/
├── app/                         # оболочка, маршруты, общие стили
├── modules/
│   ├── calculators/
│   │   ├── model/catalog.ts     # описание калькуляторов и полей
│   │   ├── components/          # части интерфейса расчёта
│   │   └── CalculatorPage.tsx
│   ├── numerical/               # парсер, производные, график и их интерфейс
│   ├── history/HistoryPage.tsx
│   └── reference/ReferencePage.tsx
└── shared/
    ├── history/                 # декоратор и клиент серверного API истории
    ├── hooks/useHistory.ts      # обновление истории на экране
    ├── ui/                      # Logo, NumericField
    └── utils/
        ├── errors.ts            # чистые расчётные функции
        └── format.ts            # форматирование результата
```

Расчётный слой не зависит от React. Модули объединяют логику и интерфейс конкретной задачи, а `shared` содержит общие элементы.

### Добавление калькулятора

1. Добавьте чистую расчётную функцию в `shared/utils` и проверки её существенных граничных случаев.
2. Опишите калькулятор, исходные значения и поля в `modules/calculators/model/catalog.ts`.
3. Подключите вычисление и представление результата в модуле калькуляторов, используя общие поля и форматирование.
4. Добавьте пункт навигации и маршрут; при необходимости обновите справочник.

## Численная точность

Вычисления используют JavaScript `number` — числа двойной точности IEEE 754. На экстремально больших и малых масштабах возможны потеря значащих цифр, переполнение и потеря малых приращений. Форматирование результата не увеличивает точность исходного числа.

Показанные границы погрешностей описывают неопределённость измеренных входных данных согласно формулам. Они не включают отдельную оценку ошибок машинной арифметики. Относительная погрешность при нулевом опорном значении не определена; деление запрещено, если допустимый интервал знаменателя содержит ноль.
