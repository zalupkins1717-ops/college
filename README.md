# Мера

Приложение для расчётов с погрешностями на React 19, Vite 7 и TypeScript.
Спокойный интерфейс с боковым меню, без градиентов и теней.

## Запуск

Требуется Node.js 20.19+ или 22.12+.

```sh
npm install
npm run dev
```

Адрес приложения появится в терминале.

```sh
npm run build   # проверка TypeScript и сборка в dist/
npm test        # тесты расчётных функций
npm run preview # локальный просмотр готовой сборки
```

Для размещения на статическом хостинге загрузите содержимое `dist/`.
Маршрутизация через `HashRouter` сохраняет работу внутренних страниц при обновлении браузера без настройки перенаправлений на сервере.

## Публикация на GitHub Pages

Для репозитория [`zalupkins1717-ops/college`](https://github.com/zalupkins1717-ops/college) подготовлен workflow `.github/workflows/pages.yml`. Файлы приложения, включая `package.json` и `package-lock.json`, должны находиться в корне репозитория.

1. В репозитории откройте **Settings → Pages** и выберите **GitHub Actions** в поле **Source**.
2. Отправьте изменения в ветку `main`. Публикация начнётся автоматически; повторный запуск доступен в **Actions → Deploy Мера to GitHub Pages → Run workflow**.
3. Дождитесь успешного завершения задач **Test and build** и **Publish website**. Ссылка на сайт появится в результате публикации и в **Settings → Pages**.

Адрес после успешной публикации: [zalupkins1717-ops.github.io/college/](https://zalupkins1717-ops.github.io/college/).

Workflow использует Node.js 24, устанавливает зависимости по `package-lock.json` через `npm ci`, запускает `npm test` и `npm run build`, затем публикует только содержимое `dist/`. При ошибке тестов или сборки новая версия сайта не публикуется. Последующие изменения в `main` обновляют сайт автоматически; одновременные публикации выполняются последовательно.

В Vite настроен относительный путь `base: './'`, поэтому ресурсы загружаются из `/college/`. Внутренние адреса имеют вид `/college/#/area` благодаря `HashRouter`. Отдельная ветка `gh-pages`, файл `.nojekyll` и личный токен для workflow не требуются.

Схема публикации следует [официальной инструкции GitHub Pages для собственных workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Возможности

Пять калькуляторов охватывают исходные задания:

- **Фактическая погрешность:** абсолютная и относительная ошибки приближения.
- **Округление и усечение:** сравнение результатов, фактических ошибок и их границ.
- **Арифметические операции:** сложение, вычитание, умножение и деление с границами погрешностей.
- **Площадь прямоугольника:** единицы измерения, диапазон возможной площади и проверка процентного допуска.
- **Вычитание близких чисел:** рост относительной погрешности при малой разности.

Поддерживаются ввод десятичной запятой, проверка исходных данных, формулы и шаги решения, примеры и сброс полей. История хранит до 50 расчётов в `localStorage` текущего браузера; результаты можно выгрузить в CSV. Справочник объясняет используемые обозначения и формулы.

Приложение работает в браузере. Сервер, учётная запись и внешние ИИ-сервисы не нужны.

## Структура

```text
src/
├── app/                         # оболочка, маршруты, общие стили
├── modules/
│   ├── calculators/
│   │   ├── model/catalog.ts     # описание калькуляторов и полей
│   │   ├── components/          # части интерфейса расчёта
│   │   └── CalculatorPage.tsx
│   ├── history/HistoryPage.tsx
│   └── reference/ReferencePage.tsx
└── shared/
    ├── hooks/useHistory.ts      # сохранение и чтение истории
    ├── ui/                      # Logo, NumericField
    └── utils/
        ├── errors.ts            # чистые расчётные функции
        └── format.ts            # форматирование результата
```

Расчётный слой не зависит от React. Модули объединяют логику и интерфейс конкретной задачи, а `shared` содержит общие элементы.

### Добавление калькулятора

1. Добавьте чистую расчётную функцию в `shared/utils` и проверки её существенных граничных случаев.
2. Опишите калькулятор, исходные значения и поля в `modules/calculators/model/catalog.ts`.
3. Подключите вычисление и представление результата в модуле калькуляторов, используя общие поля и форматирование.
4. Добавьте пункт навигации и маршрут; при необходимости обновите справочник.

## Численная точность

Вычисления используют JavaScript `number` — числа двойной точности IEEE 754. На экстремально больших и малых масштабах возможны потеря значащих цифр, переполнение и потеря малых приращений. Форматирование результата не увеличивает точность исходного числа.

Показанные границы погрешностей описывают неопределённость измеренных входных данных согласно формулам. Они не включают отдельную оценку ошибок машинной арифметики. Относительная погрешность при нулевом опорном значении не определена; деление запрещено, если допустимый интервал знаменателя содержит ноль.
